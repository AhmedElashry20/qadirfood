# دورة حياة الطلب

الحالات ومَن يملك حق تغييرها. أي انتقال مش موجود في الجدول ده بيترفض من `OrdersService` (المرجع البرمجي: `ORDER_TRANSITIONS` في `packages/shared/src/enums.ts`).

```
                      ┌──────────── REJECTED (المطعم — بسبب إلزامي)
                      │
PENDING ──────────────┼──── ACCEPTED ──── PREPARING ──── READY ──── CAPTAIN_ASSIGNED
  (وارد)              │     (+ وقت تحضير)                                    │
  عداد + صوت تنبيه    │                                                       │
                      └──────────── CANCELLED (عميل قبل القبول / أدمن)        │
                                                                              ▼
                            DELIVERED ◄──── ON_THE_WAY ◄──── PICKED_UP ◄──────┘
```

| الحالة | مين يغيّرها | اللي بيحصل في السيستم |
|---|---|---|
| `PENDING` | إنشاء الطلب (عميل) | إشعار `order:new` لغرفة الفرع → صوت تنبيه متكرر في تطبيق المطعم لحد ما يترد عليه. عداد `NEW_ORDER_ALERT_TIMEOUT_SECONDS` — لو عدّى، ينبّه الأدمن. |
| `ACCEPTED` | المطعم | إلزامي معاه `prepMinutes`. لو حالة الفرع `BUSY` بيتضاف `busyExtraMinutes` تلقائياً. ده اللي بيحدد **توقيت إرسال الكابتن**: البحث عن كابتن بيبدأ عند `acceptedAt + prepMinutes − وقت وصول الكابتن المتوقع`. |
| `PREPARING` | المطعم (أو تلقائي بعد القبول) | — |
| `READY` | المطعم (زر «جاهز») | إشعار `order:ready` للكابتن المسند + عرض `pickupCode` للمطابقة. |
| `CAPTAIN_ASSIGNED` | السيستم (خدمة الإسناد) | أقرب كابتن `ONLINE` داخل `CAPTAIN_SEARCH_RADIUS_KM` (استعلام PostGIS/Redis GEO) ياخد `trip:offer` بمهلة `TRIP_OFFER_TIMEOUT_SECONDS`؛ لو رفض أو المهلة عدّت، يروح للتالي. |
| `PICKED_UP` | الكابتن | يتطلب مطابقة `pickupCode` مع المطعم. |
| `ON_THE_WAY` | الكابتن | يبدأ بث `captain:location` كل ٥ ثواني لغرفة `order:{id}` → خريطة العميل. |
| `DELIVERED` | الكابتن | إغلاق مالي: عمولة المنصة + مستحق الكابتن + إضافة للتسوية. |
| `REJECTED` | المطعم | `rejectReason` إلزامي. يدخل في معدل الرفض في التقارير. |
| `CANCELLED` | العميل (قبل `ACCEPTED`) أو الأدمن (أي وقت) | لو الدفع تم، يتعمل استرجاع. |

## قواعد مهمة

- **كل انتقال بيتسجّل** في `order_events` (مين + إمتى + ملاحظة) وبيتحط له طابع زمني في `orders` — الأساس للتقارير و SLA.
- **الحساب المالي** بيتقفل عند `DELIVERED` بس، مش قبلها.
- **حالة Offline**: لو تطبيق المطعم فقد الاتصال، السوكيت بيفصل → السيرفر يعتبر الفرع غير مستجيب ويوقف توجيه طلبات جديدة له، ويطلع تحذير كبير في التطبيق + إشعار للأدمن.
