# قادر فود — منصة توصيل طلبات متكاملة

منصة توصيل سعودية كاملة، شغّالة **لايف** زي أي تطبيق توصيل حقيقي:
**تطبيق عميل + تطبيق كابتن + تطبيق مطعم + لوحة أدمن + لوحة مطعم + باك إند لحظي**.

> **الحالة:** كل الشاشات حقيقية ومربوطة بالـ API — **مافيش بيانات وهمية**. المنصة
> تنبض بطلبات حقيقية بتتحرك من الطلب للتسليم على الخريطة، والأرقام كلها من قاعدة
> البيانات. القلب المالي مغطّى بـ **٨١ اختبار آلي**. التطبيقات بتتبني لـ **أندرويد و iOS**.
>
> **التكاملات الحقيقية جاهزة:** دفع إلكتروني بـ **ميسّر (Moyasar)** — مدى/Apple Pay/بطاقات
> (+ كاش) · رسائل **OTP حقيقية** (Unifonic) · إشعارات **Push (FCM)** · **GPS حقيقي** لبث
> موقع الكابتن · بذرة إنتاج نضيفة + **توقيع إصدار** + **Docker/HTTPS** — كلها بتشتغل لحظة ما
> تحط مفاتيحك. شوف [النشر للمتاجر](#النشر-للمتاجر-جوجل-بلاي--آبل-استور) و[دليل الإنتاج](docs/08-production-runbook.md).

## المزايا (كلها متبنية ومتأكدة على السيرفر الحي)

**دورة الطلب:** إنشاء (تسعير من الداتابيز) → قبول المطعم → تجهيز → إسناد كابتن
(dispatch بالقرب + عروض ومهلة) → استلام بكود → في الطريق (تتبّع حي على الخريطة) →
تسليم → تقييم. آلة حالات صارمة تمنع أي قفزة غير مسموحة.

**المال (مغطّى باختبارات):** تحصيل/استرداد بواجهة بوابة مجرّدة · `paymentStatus`
مشتق مش مخزّن · موافقة مزدوجة على الاسترداد الكبير (فصل مهام) · سياسة عمولة
الاسترداد حسب المسؤولية · **تسويات المطاعم** (كل رقم له سطر، `netPayout`=مجموع
السطور) · **شركات الأسطول بالطرفين** (المنصة→الشركة، الشركة→المناديب) · محفظة
الكابتن وسحبه · فاتورة **ZATCA المرحلة الأولى** (QR بترميز TLV صح للعربي).

**التشغيل:** توزيع ذكي · نسبة قبول من عروض حقيقية · ورديات وساعات اتصال ·
**مناطق توصيل بتسعير لكل منطقة** · تسعير الطلب بياخد رسومه من منطقة العنوان.

**الالتزام والأمان:** وثائق الكباتن + منع التوزيع على المنتهية · **ربط هيئة النقل**
(بطاقة توصيل، واجهة مجرّدة) · **تحقق يومي بالوجه** (سيلفي إلزامي قبل الشغل) ·
**صلاحيات مفصّلة (RBAC)** مفروضة فعلاً · **سجل تدقيق** لكل إجراء حسّاس.

**الدعم والجودة:** نظام **تذاكر دعم** بمحادثة حيّة (عميل ↔ أدمن) · لوحة **جودة**
(تحليل تقييمات وشكاوى) · **إدارة فريق اللوحة**.

**اللوحة:** مركز قيادة لايف (كروت بتنبض مع الطلبات) · **خريطة حيّة** (Leaflet/OSM،
الكباتن بيتحركوا) · تحليلات BI · وكل شاشة في القائمة الجانبية حقيقية.

## التشغيل السريع (تطوير)

**المتطلبات:** Node ≥ 20 · Flutter 3.44 · Docker · (للـ iOS: Xcode · للأندرويد: Android SDK + NDK 27.1)

```bash
# 1) قاعدة البيانات والكاش
cp .env.example .env            # عدّل المفاتيح لو محتاج
docker compose up -d db redis

# 2) الباك إند
cd apps/api
npm install
export DATABASE_URL=... (من .env)
npx prisma db push             # إنشاء الجداول
npm run seed                   # بيانات تجريبية + حسابات دخول
npm run build && node dist/main.js   # http://localhost:3000  (API + Swagger على /docs)

# 3) لوحة الأدمن
cd apps/admin-web && npm install && npm run dev   # http://localhost:5174

# 4) تطبيقات Flutter (على محاكي/جهاز)
cd apps/customer_app && flutter pub get && flutter run
cd apps/captain_app  && flutter pub get && flutter run
cd apps/merchant_app && flutter pub get && flutter run
```

> العنوان بيتظبّط تلقائياً: iOS = `localhost`، **إيموليتر أندرويد = `10.0.2.2`**.
> لجهاز حقيقي: `flutter run --dart-define=API_URL=http://<ip-الشبكة>:3000`.

### 🔴 الداتا لايف (العرض)
علمين في `.env` بيخلّوا المنصة تنبض (تطوير/عرض بس، بيتعطّلوا في الإنتاج):
- `LIVE_SIM=1` — الكباتن بيتحركوا على الخريطة.
- `DEMO_FLOW=1` — طلبات حقيقية بتتعمل وتوصّل تلقائياً كل ~١٢ ثانية (عبر نفس
  خدمات النظام — مش أحداث مزيّفة). للإنتاج خلّيهم `0`.

## النشر للمتاجر (جوجل بلاي + آبل استور)

التطبيقات **جاهزة للتوقيع والرفع**: أيقونات احترافية، أسماء حزم ثابتة
(`com.qadirfood.customer_app` / `captain_app` / `merchant_app`)، أذونات (موقع/كاميرا)
موصوفة، ومفتاح توقيع إصدار حقيقي (`keystores/qadirfood-upload.jks`).

```bash
# أندرويد — بيبني الـ AAB الموقّع للتطبيقات الثلاثة (بيظبط اللغة عشان bundletool):
API_URL=https://api.your-domain.sa scripts/build-release.sh
# المخرجات: apps/<app>/build/app/outputs/bundle/release/app-release.aab → ارفعها على Play Console
```

> **مفتاح التوقيع:** موجود في `keystores/qadirfood-upload.jks` (وكلمة سرّه في
> `keystores/.password.txt`). **احتفظ بنسخة آمنة منه** — لو ضاع مش هتقدر تحدّث التطبيق أبداً.
> الملفات دي متجاهَلة من git.

- **iOS (App Store):** المشروع جاهز (Bundle IDs `com.qadirfood.*App`، أذونات، أيقونات).
  البناء والرفع يحتاجوا **Mac + Xcode + حساب Apple Developer بتاعك**:
  `flutter build ipa --release --dart-define=API_URL=https://api.your-domain.sa`
- **محتوى المتجر جاهز:** [بيانات المتاجر](docs/store/) (عربي/إنجليزي) · [سياسة الخصوصية](docs/legal/) ·
  [إفصاحات البيانات](docs/store/data-safety.md).

### بناء يدوي (تطبيق واحد)
```bash
cd apps/<app> && flutter build apk --release --dart-define=API_URL=https://...   # APK للتجربة
cd apps/<app> && flutter build appbundle --release --dart-define=API_URL=https://...  # AAB للمتجر
```
> نسخة الإصدار **بترفض** أي عنوان غير HTTPS — لازم تمرّر `--dart-define=API_URL=https://...`.

## التأمين والصلابة (مراجعة إنتاج)
اتعملت مراجعة جاهزية إنتاج واتصلّحت كل الثغرات الحرجة: **منع تكرار حركات الفلوس**
(انتقالات الطلب ذرّية بشرط الحالة، أقفال `FOR UPDATE` على المحفظة والسحب، مطالبة
ذرّية على الاسترداد) · **Rate limiting** على الدخول/OTP · رمز OTP تشفيري وعدم تسريبه
(fail-closed) · صلاحيات الغرف في السوكيت بالملكية · منع تصعيد صلاحيات النفس (RBAC) ·
فحص إقلاع بيرفض الإعداد غير الآمن · تطبيقات الموبايل بترفض غير-HTTPS في الإصدار ·
تصحيح تسوية المطعم (الأكل بس، من غير توصيل/ضريبة).

## قبل النشر للإنتاج — باختصار
اقرأ [دليل النشر](docs/07-deployment.md) كامل. أهم النقاط:
`DEMO_FLOW=0` و`LIVE_SIM=0` · غيّر كل الباسوردات وشيل حساب الديمو · قاعدة بيانات
وRedis إنتاج · دومين HTTPS · مفاتيح بوابة دفع حقيقية · اعتماد ZATCA المرحلة ٢ ·
API هيئة النقل · Firebase FCM للإشعارات · مزوّد SMS للـ OTP · تخزين S3 ·
حسابات Apple Developer + Google Play.
